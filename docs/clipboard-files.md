# 剪贴板与文件传输

v0.5.0、协议 5。沿用连接中心转发，文件和剪贴板不会进入键鼠的网络连接或命令队列。客户端 B 向 C 发送文件时，中心只转发有界数据块，不在中心磁盘落地文件。所有设备需要使用 v0.5.0。

## 数据通道

中心监听一个动态 TCP 端口。每个已认证控制连接获得随机 128 位票据，通过控制连接加密发送端口和票据。数据连接重新进行 Noise 握手，并提交票据；票据绑定设备身份和当前控制连接，控制连接结束即失效。中心从认证连接确定来源，忽略客户端声称的来源 ID。

独立线程、独立有界队列、32 KiB 二进制数据块。每个方向的总量由令牌桶限速，默认 8 MiB/s，运行中修改即时生效。接收限速停止继续读数据以形成 TCP 反压，中心按目标保持队列顺序，多个文件轮流发送。数据通道自动重连，已中断的文件需要重新发送；文件故障不关闭键鼠连接。

## 自动剪贴板

独立剪贴板线程约每 150 ms 检查 Windows 序列号；共享关闭时只更新观察基线，不读取内容。新文本或图像经 SHA-256 去重，使用逻辑时钟与来源设备组成版本。中心在新数据连接建立时同步时钟，避免重启设备的新复制被老设备的高版本拒绝。

接收端只接受更新版本；写入前再次检查版本及本机剪贴板是否变化，避免慢传输覆盖本机新复制。成功写入后记录序列号和摘要，阻止回环。操作失败只记录错误，不进入输入故障处理。文本/图像从数据通道分块接收，分别限制为 16 MiB / 128 MiB，内存接收预留总量最多 256 MiB。

自动同步面向整个工作组，可以关闭；手动发送面向选中设备。文件复制读取 CF_HDROP，仅提取本机路径、名称、大小和修改时间。线上 FileList 只含随机令牌、名称和 64 位大小，不包含本机路径或文件正文。每批最多 64 个普通文件，列表最多 128 KiB。复制文件夹或不支持的内容时撤销上次文件列表，不清空其他应用的剪贴板。

## 原生 Ctrl+V 文件粘贴

接收端在专用 STA 剪贴板线程调用 OleSetClipboard，发布 IDataObject；支持 FileGroupDescriptorW、按索引读取的 FileContents/IStream、复制语义的 Preferred DropEffect，以及 IDataObjectAsyncCapability。Windows 资源管理器决定粘贴的目标目录和重名处理。Ctrl+V、右键粘贴及共享键盘的 Ctrl+V 都走系统原生流程，不拦截粘贴键，不模拟按键，也不探测资源管理器当前路径。接口依据 [Shell 数据对象](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject) 和 [Shell 剪贴板格式](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)。

1. 复制后只发布文件列表；查询格式、文件名或文件大小不会下载正文。
2. Windows 请求 FileContents 时，接收端向原设备发送 Pull（请求 ID、剪贴板令牌、索引）。源端只允许打开自己当前复制列表中的文件，检查共享开关、剪贴板版本、大小及修改时间，不接受远端传来的任意路径。
3. 源端沿用现有文件流协议，以同一个请求 ID 返回 Offer。接收端只有在来源、名称、大小与待粘贴请求一致时自动接受；其他文件仍需手动接收。
4. 正文下载到 `%TEMP%\MWB-Rust-clipboard\设备ID\随机任务ID`。固定大小块流式落盘，SHA-256 与长度验证通过后，才允许 IStream 读取。默认 8 MiB/s 限速、进度及应用内取消沿用现有传输逻辑。
5. IStream 支持 Read、Seek、Stat、Clone、CopyTo；长度和偏移保留 64 位。等待下载时持续分派 STA 消息，网络收发和键鼠线程独立。Windows 异步操作失败或取消会撤销尚未完成的下载；应用内取消可立即唤醒等待的流。
6. 同一剪贴板重复粘贴复用已校验磁盘缓存；失败后重新粘贴会新建请求。最后一个剪贴板/流引用释放时，仅删除本任务文件及空的随机任务目录。取消、断线、校验失败清除本次未完成文件；停止工作组唤醒全部等待者。异常退出可能留下临时缓存，当前不自动清扫其他进程的缓存。

源设备离线时，即使接收端仍连接中心，也会根据工作组状态立即终止等待。新复制会撤销旧列表的新下载权限；已经打开的传输可以继续。暂停或关闭自动剪贴板只在 OleIsCurrentClipboard 返回 S_OK 时清理本程序拥有的远端文件对象，不误清用户本机剪贴板；S_FALSE 不能按普通成功处理。

文件始终按复制处理，源端 Ctrl+X 也不会导致远端删除源文件。支持普通文件，暂不递归文件夹。仅支持 CF_HDROP 的接收应用可能无法粘贴虚拟文件；主要目标为 Windows 资源管理器。接收端临时盘和目标盘都需足够空间；Windows 写入目标的进度和最终错误由 Windows 报告，本程序的完成状态表示下载及校验已完成。资源管理器在下载阶段可能显示准备中。

## 文件生命周期

1. 用户选择普通文件或读取剪贴板文件，工作线程验证并打开源文件；每批最多 64 个。
2. 发送名称和 64 位长度；接收端显示邀请。文件没有固定大小上限，不按整个文件分配内存。
3. 用户接受后，在选定目录以 create_new 创建随机 .part 文件。拒绝路径分隔符、绝对路径、ADS、保留名称和尾随点/空格；远端只能提供单个文件名。
4. 顺序读写固定大小块，校验来源、任务 ID、偏移及累计长度，持续更新进度；双方增量计算 SHA-256。
5. 接收长度与摘要一致后同步磁盘，使用不替换已有目标的 MoveFileW 提交；重名改用带编号的名称，完成后通知发送端。
6. 拒绝、取消、断线、超时或错误会释放句柄并删除本次创建的临时文件，不删除源文件或已完成文件。

文件传输不实现目录递归、断点续传或远程自动执行。磁盘满、权限不足和文件系统容量限制仍可能使传输失败；应用层没有 100 MB 或 4 GiB 文件阈值。发送过程中不能保证被其他程序修改的源文件是某个时间点的一致快照。

## 验证范围

核心测试使用三个 Runtime、真实 TCP/Noise、本地临时文件和替代输入/剪贴板后端。覆盖自动文本/图片、防回环、暂停/开关、重新加入的时钟同步、在途旧内容、多文件/空文件、同名保护、拒绝与中断清理、乱序/损坏拒绝、64 位大小和慢接收端反压下的输入响应。新增文件列表不预下载、按需粘贴、重复缓存、取消重试、源文件修改、旧列表撤销、快速开关、来源离线和输入持续可用。

原生 COM 测试覆盖格式枚举、Unicode / 5 GiB 描述符、复制语义、非法索引/介质拒绝、跨线程封送和流读取/Seek/Clone/EOF。单独调用 Windows Shell 目录的 IDropTarget，以默认异步模式实际接收中文文件和空文件，不操作系统剪贴板。另完成 128 MiB 文件从加入端经中心到另一加入端，再由原生 IStream 读出，验证全文件 SHA-256；调试构建本轮耗时约 36 秒。

常规核心测试 58 项通过；Shell 和 128 MiB 原生粘贴测试单独通过。限速测试持续检查输入响应。测试不安装全局钩子、不移动光标、不修改系统剪贴板。桌面自动化运行时仍有沙箱初始化故障，真实资源管理器的 Ctrl+C/Ctrl+V 与实体多机网络体验需要实机验收。
