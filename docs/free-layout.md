# 多设备工作组与自由布局

自 v0.3.0 起使用一个连接中心与多个加入端，每条连接独立握手、加密、心跳和重连。连接线程只处理网络；每台机器的工作组循环独占输入注入及路由状态。

## 几何模型

DeviceInfo 包含稳定 ID、名称、虚拟桌面物理像素边界和各显示器矩形。Device.x/y 是设备桌面左上角的共享画布坐标，显示器相对桌面的偏移保持不变。设备可以整体任意平移，没有行列、边缘吸附或上下左右槽位。

校验只拒绝不同设备的实际屏幕相交；外包围框可以在没有屏幕的空白处重叠。跨屏时从源屏幕边缘沿移动方向发射射线，选择最近的在线屏幕，跳过空白。如果当前设备自己的其他显示器更近，则交给 Windows 自然移动。

落点映射回目标本地物理坐标并内缩 4 像素，保留实际对齐位置。100 ms 切换保护和可选 100 像素角落保护继续有效。屏幕信息启动时读取，热插拔和分辨率变化暂需重启刷新。

## 布局提交与持久化

中心维护共享布局和修订号。所有节点收到相同的设备列表、尺寸、位置和在线状态。UI 拖动草稿，点击保存后提交位置和基准修订号，不允许通过位置修改伪造屏幕尺寸。

中心验证设备数量、ID、坐标和屏幕重叠；过期修订拒绝并返回当前布局。提交成功先结束旧远控，再广播新布局；UI 写入本机配置。重连按稳定 ID 恢复位置，离线保留设备；新尺寸造成重叠时将该设备移到右侧空闲处，随后可重新拖动。

## 控制会话

中心为每次控制分配递增 epoch，并广播控制端、目标、模式和落点。一个工作组只存在一个远控会话，竞争请求按中心处理顺序接管。

- 控制端在捕获时绑定 epoch，包括本地异步队列；切换后排队的旧点击和按键不会落到新目标。
- 中心只转发当前控制端的当前 epoch 输入，只有目标注入。B→C 经 A 中转时，A 不代替 C 注入。
- 切换、布局修改、暂停、物理接管和相关设备断线时释放按键。无关设备断线不影响现有控制。
- 比例模式按源主屏与目标桌面尺寸比累计位置，保留小数，线上位置为目标物理像素。
- 相对模式直接 MOVE 注入，目标每约 8 ms 报告真实位置，控制端根据反馈和最近方向选择下一个设备。
- 注入错误暂停故障节点但保留连接；剪贴板系统错误单独记录。

## 网络边界

当前 v0.5.0 线协议为 5，所有设备必须升级。Hello 交换身份/屏幕；Topology 广播布局；Arrange 修改位置；TakeControl、Control、Release 管理控制；Input、Cursor 承载输入/反馈。DataChannel 协商独立的剪贴板/文件通道，详见 [数据传输设计](clipboard-files.md)。

队列与帧大小有限，最多 16 台设备、每台 16 块屏幕，位置限制 ±1,000,000，尺寸上限 65,536。中心是可信节点，能看到转发内容；加密保护每条到中心的链路。暂不支持中心自动选举或完全分布式路由。

## 代码入口

| 模块 | 职责 |
| --- | --- |
| layout.rs | 元数据、自由位置、重叠校验、射线命中 |
| network.rs | 并发 Noise/TCP、握手、队列、心跳、重连 |
| engine.rs | 工作组、布局修订、控制会话、路由 |
| motion.rs | 比例位移累计及像素中心归一化 |
| platform/windows.rs | 真实显示器枚举、钩子、SendInput |
| main.rs | 缩放、平移、拖动、设备选择、布局保存 |
| engine/tests.rs | 三个 Runtime 的真实加密回环测试 |

测试验证 B→C 转发、A→B→C→A 连续切换、竞争控制、旧 epoch 隔离、共享布局冲突、断线与故障恢复。测试桩替代真实注入，不操作用户桌面。
